# 书源页重设计研究（v0.6.47 已实施）

> 状态：**已实施**（v0.6.47）。本文档保留作设计依据与验收对照。
> 落地实现见 `web/js/ui/sources.js` 与 `styles.css` 的「书源列表」段；预览稿 `/workspace/书源页改版预览.html`。
> 目标：把「功能齐全但东拼西凑」的书源管理，重做成「有统筹、一眼能懂、好操作」的页面。

---

## 一、现状问题诊断（为什么会"东拼西凑"）

当前 `web/js/ui/sources.js`，功能链路是逐轮补出来的（导入 → 校验 → 全选校验 → 漏斗筛选 → 查重 → 批量启停 → 导出报告），每个功能各加了一块 UI，缺少统一的信息架构。具体表现：

| 问题 | 现状 | 后果 |
|---|---|---|
| 顶栏无主次 | 6 个按钮平铺：导入 / 校验全部 / 检查重复 / 筛选 / 载入示例 / 导出全部 | "导入"这种主操作和"查重"这种低频操作同级；一行塞不下时更难看 |
| 卡片信息过载 | 每张卡 = 开关 + 分组/搜索/发现/登录态标签 + 校验状态标签 + **内联可展开的失效原因** + 4 个 mini 按钮（校验/编辑/分组/删除） | 层次混乱；失效源的长原因把卡片撑破，列表节奏被打断 |
| 缺「选择态」 | 想批量删失效源，得先筛"仅失效"→ 靠筛选栏的"全部启用/禁用"；没有列表级多选 | 批量操作绕路，且"批量删除"藏得深 |
| 弹层风格不一 | 校验/查重是 `chip-row` 风格；导入是 `opt-list` 风格；编辑/分组是 `form` 模态 | 同一页面里三种交互语言，观感割裂 |
| 校验不是主流程 | 校验全部藏在二级；结果只以卡片小标签 + 顶部一行统计呈现，没有"清理失效"之类的收敛动作 | 校验完用户不知道下一步做什么，体验断在半路 |

**一句话根因**：把"功能清单"直接映射成了"按钮清单"，没有把"浏览 / 选择 / 批量操作 / 校验"分层。

## 二、优秀案例研究

书源管理是 Legado 系特有的垂直交互，**最强的参照就是开源阅读本身**；再叠加移动端原生列表范式与现代规则管理器的成熟做法，足以覆盖全部问题。

### 案例 1：开源阅读（Legado）书源管理 —— 多选态 + 底部上下文操作栏

- **列表项**：名称 + 分组 + 一个小状态点（有效/失效/未校验），极简，不堆标签。
- **入口收敛**：右上「┇」菜单放导入 / 排序 / 全选 / 导出 / 校验全部，主按钮不挤占顶栏。
- **多选态**（核心借鉴）：长按或勾选进入选择 → 顶部显示"已选 N" + 全选，底部浮现**操作栏**
  （启用 / 禁用 / 删除 / 分组 / 校验 / 排序 / 导出）。批量动作从"藏在筛选里"变成"选中即出现"。
- **校验流程闭环**：校验全部有独立进度；完成后失效源标记红色，提供「移除失效」一键收敛。

> 借鉴点：批量管理书源就该用"选择 → 底部上下文栏"，而不是把动作平铺或塞进筛选。

### 案例 2：iOS / ColorOS 17 原生列表范式（本 App 已采用 ColorOS 控件语言）

- **编辑态**：圆形勾选圈 + 列表左移，顶部"全选 / 取消"，底部工具栏——与案例 1 同构，证明这是跨平台共识。
- **滑动单条操作（swipe）**：尾随"删除"、前导"更多"，适合"只处理一条"的高频动作，与多选态互补。
- **状态表达**：用系统色（绿=有效、红=失效、灰=未校验）的**小圆点/图标**，而不是一整串文字标签。

> 借鉴点：单条用 swipe，多条用多选；状态用色点。卡片里那排 mini 按钮可以整体撤掉。

### 案例 3：现代规则 / 扩展管理器（VS Code 扩展、1Password、Raycast）

- 顶部 **搜索 + 分组筛选**常驻但可折叠；每行紧凑，状态用图标/色点，主操作在"选中后"才出现。
- 详情类信息（如失效原因）走**独立抽屉/详情页**，不内联撑破列表。

> 借鉴点：失效原因不该 inline 在卡片里，应点开看详情。

## 三、重设计方案

### 信息架构（分层）

```
书源管理
├─ 顶栏：标题「书源管理」+ 计数（共 N · 启用 M）   右侧 ┇ 菜单（导入 / 校验全部 / 导出 / 排序 / 管理分组）
├─ 可收起搜索行（点 🔍 展开）
├─ 可折叠筛选 chip 行（校验结果 / 启用 / 分组，常驻但折叠，不占主按钮位）
├─ 列表（组件化卡片）
└─ 多选态激活时 → 底部浮动操作栏（启用 / 禁用 / 删除 / 分组 / 校验 / 导出选中）
```

### 列表项（新组件）

```
[○]  书名（serif）            [开关]
     分组 · 搜索/发现         ● 有效/失效/未校验
     （左：选择圈，多选态才显；右：启用开关）
     单条 swipe → 删除 / 更多
     点卡片 → 详情抽屉（含失效原因、规则摘要、编辑入口）
```

- 撤掉卡片内 4 个 mini 按钮 + 内联原因。
- 状态用色点：有效 `#5E6B5A` / 失效 `#A8433A` / 未校验 `#A79C84`。
- 校验失败：色点变红 + 卡片右侧一个小"!"角标，点开详情看原因。

### 交互状态机

```
浏览态 ──勾选/长按──▶ 多选态（顶部计数+全选，底部操作栏）
   ▲                      │
   └──── 取消/全不选 ─────┘
浏览态 ──点卡片────▶ 详情抽屉（原因/编辑/分组）
浏览态 ──swipe────▶ 单条 删除/更多
┇ 菜单 ──校验全部──▶ 进度 ──▶ 标记 + 「清理失效」入口
```

### 视觉规范（沿用纸墨 + ColorOS 17）

- 卡片：圆角胶囊、`--card` 底、柔和投影（与书架卡同语言）。
- 底部操作栏：浮动胶囊卡，与阅读页工具坞同形态（两行/单行均衡，圆润无描边）。
- 选择圈：ColorOS 风格圆环；swipe 尾随按钮红色"删除"、前导中性"更多"。
- 弹层：导入/筛选/校验/分组**统一**为同一套 sheet/模态风格（目前三种混用，要收一种）。

## 四、实施清单（后续，按此落地）

1. **顶栏收敛**：6 按钮 → 标题+计数 + ┇ 菜单（导入/校验全部/导出/排序/管理分组）+ 可收起搜索。
2. **列表项组件化**：选择圈 / 启用开关 / 状态色点 / swipe 删除·更多；撤内联 mini 按钮与 inline 原因。
3. **多选态 + 底部操作栏**：启用 / 禁用 / 删除 / 分组 / 校验 / 导出选中（替代"筛选栏批量"）。
4. **校验闭环**：┇→校验全部进度；完成标记 + 顶部"清理失效"一键（替代零散的"导出报告"入口）。
5. **筛选改顶部可折叠 chip 行**：常驻但折叠，不占主按钮位。
6. **详情抽屉**：点卡片看失效原因 / 规则摘要 / 编辑，不再撑破列表。
7. **弹层风格统一**：导入/筛选/分组/编辑收敛为一种 sheet + 一种模态。

---

## 五、验收（做完对照）

- 顶栏一眼能分清主次，不再 6 按钮平铺。
- 任意多选 → 底部操作栏出现，批量删除/启停 ≤ 2 步。
- 列表卡片信息密度下降，失效原因不再 inline 破坏节奏。
- 校验完有收敛动作（清理失效），流程闭环。
- 所有弹层同一视觉语言。
